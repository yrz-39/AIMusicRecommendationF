# 追加：第二次推进（同日晚）—— 听歌检测闭环打通 🎧

> 回答所有者的三个问题：检测网易云播放？自然语言反馈存库？一键基于当前歌推荐？——**现在全部是"是"**。

## 完成了什么

把"正在听什么 → 对它说话 → 找到类似的歌"整条链路做成了产品功能：

1. **正在播放条**：推荐页顶部新增常驻条，每 6 秒轮询桌面客户端（网易云/QQ 音乐窗口标题）。检测到播放且曲库里有这首歌时显示「🎵 正在播放：《夜曲》 - 周杰伦」+ 两个动作按钮；没检测到播放时整条隐藏不打扰；检测不到播放来源或歌不在曲库时给出明确提示（"去音乐库添加后才能教它"）。
2. **「教它」一键学习**：正在播放条上直接展开输入框，对当前歌说"这首歌很安静，能让我静下心来"→ 解析为特征增量（能量按 0.3 学习率混合 + 新增情绪标签）→ 存入 `learnEvents.json`，**之后所有推荐立即受影响**。实测《夜曲》："很安静能静心" → 能量 0.57→0.48 + 新增 calm/soothing 标签。
3. **「基于这首歌推荐」一键找相似**：新增 `POST /api/recommend-similar`——由曲目特征直接构造推荐情境（能量三档映射走引擎"明确表达"路径、纯音乐→无人声偏好、流派带入偏好），排除基准曲目自己，返回带真实理由的 10 首。实测《夜曲》→ 全是 pop/hiphop/post-rock 适中能量曲目，结果头显示"基于《夜曲》为你选了 10 首"，理解面板置信度 100%。

## 过程中发现并修复的关键 Bug

**听歌检测在中文 Windows 上从未真正工作过**：PowerShell 默认按 GBK 输出窗口标题，Node 按 UTF-8 解码全部变成乱码，"网易云"标记永远匹配不上。此前只测试过标题解析纯函数，execFile 编码链路从未联调过（上次报告把它列为"待联调"）。修复：PowerShell 脚本开头显式 `[Console]::OutputEncoding = UTF8`。**用模拟网易云窗口（WinForms 窗口标题=《夜曲》 - 周杰伦 - 网易云音乐）做了端到端验证**：检测 → 曲库匹配 → UI 展示 → 一键学习 → 一键相似推荐，全链路实测通过。

## 已知边界（诚实说明）

- 检测依赖网易云/QQ 音乐**桌面客户端**的窗口标题，网页版播放检测不到；窗口最小化到托盘时标题可能拿不到（后续 Electron 原生方案可解）；
- "类似这首歌"的能量经三档映射有量化损失（0.57→目标 0.5），换取理由链路完全可解释；
- 自然语言"教它"目前是**规则解析**（能理解"给我力气/很安静/没歌词"这类表达），LLM 版实现同一契约即可替换——需要你提供 API key。

## 四、核心设计细节

### 4.1 规则式情境解析器（`rulesParser.ts`）

输入"今晚准备写代码两个小时，有点累，而且容易走神。想听安静一点、歌词少一点的音乐。"输出：

```json
{ "task": "写代码", "durationMinutes": 120, "energy": "medium", "focusDifficulty": "high",
  "musicPrefs": { "calmness": "calm", "vocalPreference": "few-lyrics" }, "置信度": 0.87 }
```

设计要点：
- **只输出真正读到的信息**，缺失字段留在 `unknowns`（"未提及：压力水平、情绪"），由引擎用稳健默认值兜底——绝不编造；
- 每个结论记录命中的原始关键词（`matched`），UI 上可见，保证可解释；
- **特例规则先于一般规则**（"有点累"=中 必须先于"累"=低 判定），所有赋值带防覆盖保护——这是当日 bug 修复之一；
- 中文数字/时长解析：`两个小时`→120、`一个半小时`→90、`四十五分钟`→45、`一下午`→180。

### 4.2 推荐引擎（`engine.ts`）—— 六维评分

每首曲子得 0–100 分，六个分项加权求和：

| 分项 | 权重 | 逻辑 | 理由示例 |
|---|---|---|---|
| context | 0.36 | 1 − \|曲目能量 − 目标能量\| | "曲目安静舒缓，你明确想要安静的音乐" |
| vocal | 0.18 | 纯音乐/人声密度对照目标偏好 | "纯音乐没有人声，不会抢走注意力" |
| mood | 0.14 | 曲目情绪标签与期望方向的重叠 | "曲风情绪偏「平静、专注」，契合你现在的状态" |
| preference | 0.14 | 用户点名的流派/语言匹配 | "符合你点名的「Lo-Fi」风格" |
| personal | 0.12 | 反馈亲和度（见 4.3） | "你之前喜欢过这首歌" |
| freshness | 0.06 | 最近两批推荐过的降权到 0.35 | "最近刚推荐过，这次稍微靠后" |

关键机制：
- **目标能量派生链**：用户明确说"想听安静"= 0.25（说了算）→ 没说但"容易走神"= 0.35（推断）→ 全没说 = 0.5（默认）。派生来源记录在案，理由文案跟着来源走，绝不出现"事后编造的理由"；
- 曲目缺 energy 时用**流派先验表**兜底（rock 0.75 / lofi 0.3 / classical 0.3 / ambient 0.15…）；
- 同歌手最多 2 首（多样性）；同分时按"时长甜区"（2.5–7 分钟）二级排序——实测发现 top10 挤在 83.8/82.8 两个分数，这个 tie-breaker 消除了排序随意性。

### 4.3 个性化反馈（`affinity.ts`）

- like +1 / skip −0.4 / not_suitable −1，**60 天半衰期指数衰减**；
- **情境相关性**：反馈时记录情境快照（任务/精力/压力/专注），与当前情境任务相同 → 权重 1.0，不同 → 0.45，缺失 → 0.7。"写代码时不喜欢"不应该杀死"睡前听"；
- 歌手层影响减半（一首歌不封杀整个歌手）；
- **非对称上限**（核心产品原则"当前明确需求 > 历史反馈"）：喜欢最多把分数顶高 +8 分，不适合/跳过可以压低 −20 分。喜欢不该强行把歌顶上去，但"不适合"必须可靠降权。

### 4.4 歌曲特征学习（`featureLearner.ts`）—— 你的愿景支柱 3

对任意歌说"这首歌给我力气，能够提高精力，振奋精神"：

1. **解析**（当前规则版，未来 LLM 版实现同一契约直接替换）：识别出 `energyHint: high` + 情绪标签 `uplifting/bright` + 命中短语列表；
2. **融合**：能量**按学习率 0.3 混合**而非跳变——`新能量 = 旧×0.7 + 目标×0.3`（目标：high=0.72 / medium=0.5 / low=0.28）。反馈同一首歌十次，能量会收敛到 0.72 附近；说反了（"很安静"）也能拉回来；
3. **记录**：每次学习写入 `learnEvents.json`（原文 + 解析出的增量 + 变化明细），**特征是怎么来的永远可追溯**；
4. UI 上会显示"已学习：能量 0.50 → 0.57（提升）；新增情绪标签 uplifting、bright"。

实测（浏览器）：对《夜曲》说"给我力气，能够提高精力，振奋精神" → 能量 0.50 → 0.57，新增 uplifting/bright 标签。

### 4.5 歌单模式（`playlist.ts`）—— 你的愿景支柱 4 的第一步

"我现在精力比较低，要背书 40 分钟左右，想听安静的" → 解析出 `durationMinutes: 40` + `calmness: calm` → 引擎全库排序（limit 60）→ **按时长预算贪心装配**（单首超出预算 90 秒以上跳过，轻量背包）。

实测：返回 10 首、总长 41 分钟（目标 40），曲目全部是安静系（Clair de Lune / Ocean Eyes / The Rain / A Walk / Intro / Aruarian Dance…）。曲库不够时明确提示缺口。

### 4.6 听歌检测原型（`nowPlaying.ts`）—— 你的愿景支柱 2

- 原理：网易云/QQ 音乐桌面客户端播放时，窗口标题变成"歌名 - 歌手 - 网易云音乐"；
- 实现：PowerShell 枚举可见窗口标题 → 识别客户端标记 → 解析歌名/歌手（支持 `-`、`—`、`|` 分隔，过滤未播放状态标题）；
- **零凭据、零侵入**；失败一律优雅降级为 `{playing:false}`，绝不让主流程崩溃；
- 已暴露 `GET /api/now-playing`；Electron 小窗阶段可换成原生 API，解析函数不变。

### 4.7 导入系统

- **CSV**（推荐给普通用户）：粘贴或选文件；表头中英文均可（`歌名/title、歌手/artist、专辑/album、时长/duration、风格/genres、能量/energy、情绪/moodTags、语言/language、纯音乐/isInstrumental`），列序不限、缺列可省；时长支持 `"4:29"` 和秒数；完整 CSV 引号/转义/CRLF/BOM 解析器手写实现；
- **JSON**：粘贴对象数组；
- 行级校验：坏行逐行报告原因（"缺少歌手 artist"/"id 重复"），**绝不整批失败、绝不静默吞掉**；按 id 去重；
- 首次运行自动导入 82 首示例库（真实曲目、网易云可检索、标注接近真实听感的能量/情绪），只导入一次（持久化 flag），用户清空库不会被重新填充。

### 当日发现并修复的 Bug（真实根因，非表面修补）

1. `有点累` 被泛化规则抢先命中 → 特例规则优先 + 全部赋值防覆盖；
2. `not_suitable` 负反馈影响过弱（-2 分压不过 12 分情境差）→ 提高个性化权重 + 反馈情境相关性 + 非对称上限；
3. top10 同分排序随意 → 时长甜区 tie-breaker；
4. CSV 测试期望错误（3 行坏数据我写成 2）→ 修正断言；
5. 正则无 `g` 标志漏收集多个命中；`没有歌词` 匹配不上 `没歌词` → 模式修正；
6. "未提及"标签对比度过低 → 色值加深；
7. 端口残留进程（tsx watch 子进程未随父退出）→ taskkill 清理，服务重启。
